# E12 – Code review and maintenance

**Phase:** 4 · **Depends on:** – (E12-06 after E08 and E09) · **Status:** open

## Goal
Review the frontend and backend code for performance, readability, up-to-date and justified dependencies, and best practices. The result is a written report plus small, separate PRs that each fix one area. Behavior and API stay unchanged unless an issue says otherwise.

## Definition of done
- `docs/17-code-review.md` lists every finding with severity and the issue or PR that resolves it (or why it is accepted).
- CI enforces formatting, clippy, ESLint, dependency audits and the bundle budget; all green on `main`.
- No unmaintained dependency; duplicate crates removed where an upstream version allows it.
- Render benchmark and preview latency are documented and not worse than the baseline.

## Issues
- [ ] **E12-01 Review report** – Read both code bases against the checklist below and write `docs/17-code-review.md`: table *area · file · finding · severity (H/M/L) · action (issue id or "accepted: reason")*. Checklist: React (effects with complete dependencies, no state that can be derived, no work in render, stable keys, cleanup of timers/listeners/object URLs, lazy chunks), TypeScript (no `any`, narrow types at boundaries such as `parseConfig`), CSS (tokens only after E07, no dead rules), Rust (no `unwrap`/`expect` on request paths, typed errors mapped once to the JSON envelope, timeouts on every outgoing HTTP call, no secrets in logs or `Debug`, bounded concurrency, `spawn_blocking` for CPU work), security (input limits, CORS, headers, no customer data persisted), tests (critical paths covered, no flaky timing). *Files:* `docs/17-code-review.md` (new), `docs/README.md`. AC: every checklist point has a result; every H finding has an issue in this epic or a new one.
