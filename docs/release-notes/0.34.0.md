# PDFCraft 0.34.0

Release notes for `v0.34.0`. The API surface is the same as in [0.33.0](0.33.0.md); this release fixes the publishing of the npm packages.

## Changes

- The workspace packages are published under the `@maltinapro` scope: `@maltinapro/pdfcraft-design` and `@maltinapro/pdfcraft-editor` (was `@pdfcraft/design` and `@pdfcraft/editor`). GitHub Packages only accepts scopes that match the repository owner, so publishing under `@pdfcraft` failed with `403` (#249). Consumers must update their imports and set `@maltinapro:registry=https://npm.pkg.github.com` in `.npmrc`.
- The package registry and install steps are documented in [Architecture and extending](../10-architecture-and-extending.md#package-registry) (#250).
- Dependency lock file maintenance (#247).

Existing endpoints, request bodies and PDFs are unchanged.

## Artifacts

- `ghcr.io/maltinapro/pdfcraft-backend:0.34.0` and `…/pdfcraft-frontend:0.34.0` (linux/amd64 and linux/arm64)
- `oci://ghcr.io/maltinapro/charts/pdfcraft` version `0.34.0` (chart version = appVersion = release version)
- `@maltinapro/pdfcraft-design` 0.1.0 and `@maltinapro/pdfcraft-editor` 0.2.0 on GitHub Packages. Both were published with *Run workflow* (`workflow_dispatch`) on `v0.34.0`, not by tags. The tarball of the editor still contains its test files; the next editor release excludes them.

## Follow-up for maintainers

Create the package tags on the published commit so that a package version maps to a source commit (see [Package registry](../10-architecture-and-extending.md#package-registry)):

```
git tag design-v0.1.0 v0.34.0 && git push origin design-v0.1.0
git tag editor-v0.2.0 v0.34.0 && git push origin editor-v0.2.0
```

Later package releases go through these tags only (bump `version` in the package's `package.json`, then push `design-vX.Y.Z` / `editor-vX.Y.Z`).
