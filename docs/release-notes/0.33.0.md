# PDFCraft 0.33.0

Release notes for the first version that contains the upstream requests R1–R11 (#214–#224). Paste this text into the GitHub release `v0.33.0` (or use *Generate release notes* and add the sections below). Details: [API Reference](../09-api-reference.md), [OpenAPI spec](../openapi.yaml).

## New API surface

| Area | What is new | Reference |
| --- | --- | --- |
| Static service tokens (R1, #214) | Long-lived tokens `ps_…` without expiry from `SERVICE_TOKENS` / `SERVICE_TOKENS_FILE` (only SHA-256 hashes). `/v1` works without Valkey when service tokens exist. CLI: `pdfcraft-backend tokens create-service`. | [Tokens](../05-tokens-and-rate-limiting.md#static-service-tokens) |
| Draft watermark option (R2, #215) | Optional body field `options.watermark = "draft"` on `POST /v1/invoices`, `/v1/invoices/bulk`, `/v1/documents`, `/v1/documents/bulk`. | [API](../09-api-reference.md) |
| Version information (R3, #216) | `GET /v1/version` (`version`, `commit`, `typst`, `templateHash`, `templates`) and the response header `X-Pdfcraft-Version` on every response. | [API](../09-api-reference.md) |
| Deterministic output (R4, #217) | Identical input gives a byte-identical PDF on the same build (tests `pdf_output_is_identical_*`). | [API](../09-api-reference.md#deterministic-pdf-output) |
| Dunning letter (R5, #218) | `type: "dunning"` for `POST /v1/documents` and `/v1/documents/bulk` (reminder, dunning letter, final notice; fees; manual or calculated interest from the base-rate table). | [API](../09-api-reference.md) |
| Report (R6, #219) | `type: "report"` for `POST /v1/documents` and `/v1/documents/bulk` (typed tables, groups with subtotals, up to 10 000 rows, optional landscape). | [API](../09-api-reference.md) |
| E-invoice parse (R7, #220) | `POST /v1/einvoices/parse`: ZUGFeRD/Factur-X PDF (≤ 20 MB) or CII/UBL/XRechnung XML (≤ 5 MB) in, normalised invoice view plus plausibility and rule checks out. Stateless. | [API](../09-api-reference.md) |
| Structured footer (R10, #223) | `settings.footerMode: "structured"` plus the sender fields `legalForm`, `registeredOffice`, `registerCourt`, `registerNumber`, `managingDirectors`, `supervisoryBoardChair`. The default `free` keeps all PDFs unchanged. | [API](../09-api-reference.md) |
| Production Helm chart (R11, #224) | `values-production.yaml` (`/v1` only, existing Secrets, HPA, PDB, NetworkPolicy, ServiceMonitor) and `fullnameOverride` so the chart can be a dependency of another chart. | [Kubernetes / Helm](../08-kubernetes-helm-outlook.md) |

Packages (R8, R9) are released separately, see the checklist below: `@maltinapro/design` (tokens, components, icons, theme) and `@maltinapro/editor` (paper-first editor with a replaceable `EditorAdapter`).

Existing endpoints, request bodies and PDFs are unchanged unless one of the new options is used.

## Release checklist

1. `main` is green and contains the merge commits of all requests above (at least `6fbc2e6`).
2. GitHub → Releases → *Draft a new release* → tag `v0.33.0` on `main` → paste these notes → **Publish release**. `.github/workflows/release-images.yml` then publishes the images and the chart (see "Releasing" in the [chart README](../../deploy/helm/pdfcraft/README.md)).
3. Check the result: `docker buildx imagetools inspect ghcr.io/maltinapro/pdfcraft-backend:0.33.0` lists both architectures; `helm show chart oci://ghcr.io/maltinapro/charts/pdfcraft --version 0.33.0` shows `appVersion: 0.33.0`; `GET /v1/version` of the image answers `"version": "0.33.0"` and the release commit.
4. Packages, design first (the editor depends on it): `git tag design-v0.1.0 && git push origin design-v0.1.0`, then `git tag editor-v0.2.0 && git push origin editor-v0.2.0` (the versions must match the `package.json` files; the workflows check this). Set both packages to public once in the GitHub package settings.

The package tags must point to a commit containing the `@maltinapro` namespace fix. Retrying an older failed run
uses its original commit; instead, dispatch the workflows on the fixed commit or create the package tags there.
